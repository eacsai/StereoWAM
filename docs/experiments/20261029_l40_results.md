## 修正 step 计数口径

历史命名中的 bs8ga4_eff128 表示每卡 micro-batch 8、world size 4、
DeepSpeed GA 4，即每次权重更新的累计 batch 为 128。
成功的旧兼容路径不在 accelerate launch 显式传 --gradient_accumulation_steps，
train_starvla.py 使用 Accelerator(deepspeed_plugin=DeepSpeedPlugin())；
Accelerate 自身 GA 为 1，所以 Python 日志打印 Total batch size=32。

train_starvla.py 的 completed_steps 在 accelerator.sync_gradients 为真时加 1；
该旧路径每个 micro-batch 都为真。Accelerate 1.5.2 的
DeepSpeedEngineWrapper.backward 每次调用 engine.backward + engine.step，
由 DeepSpeed 自己每 4 个 micro-step 执行一次优化器更新。
因此 30,000 个该路径的日志步预期约为 7,500 次权重更新
（假设没有跳过更新），累计约 960,000 个样本，而不是 30,000 次权重更新。
这是由实现与已记录配置推导，历史未逐次记录 engine global_steps；
不得把推导值写成已读取历史 optimizer state 的测量。

把 Accelerate GA 也改为 4 会改变日志计数/样本预算，还可能触发
ZeRO-2 的 no_sync 冲突，不能仅因两组都叫 30k 就认定预算相同。
旧对照复现应采用同一版本/同一计数方式；
新实验应直接记录真实 engine optimizer/global steps、scheduler steps 和 samples_seen。
前次对话中“30k optimizer steps”的笼统说法不准确，以此处口径为准。

## 断点与环境限制

train_starvla.py 的 .pt 保存 model state_dict，不保存完整 optimizer/RNG/sampler。
load checkpoint 后按 completed_steps 调 scheduler 的逻辑不等同于精确续训。
14k 权重可用于初始化，但必须标为 weight-only resume/warm-start，
不能与连续 from-scratch 实验混称。

本次只做代码、元数据及只读/CPU 验证，没有重跑训练或 rollout，
没有重新测量上述成功率。原有数据/缓存/环境的完整性仍需接手者按实际机器核验。
